# MedQuality

Закрытый портал непрерывного повышения качества медицинских услуг. Проект объединяет обучение сотрудников, итоговое тестирование, внутренние документы и актуальную отчётность в одном интерфейсе.

## Возможности

- четыре роли: системный администратор, методист, руководитель подразделения и сотрудник;
- сотрудники, должности, типы сотрудников, отделы и отделения;
- каталог курсов с категориями;
- материалы курса: учебные документы, YouTube-видео, НПА РК и документы из внутреннего банка;
- банк внутренних документов с версиями, статусами, сроками пересмотра, тегами и повторным подключением к разным курсам;
- конструктор итогового теста с вопросами одного или нескольких правильных ответов и форматом «верно/неверно»;
- публикация и версионирование тестов с неизменяемой историей попыток;
- назначение курса отделам, отделениям или отдельным сотрудникам;
- индивидуальные срок, проходной балл и допустимое количество попыток;
- внутренние уведомления о назначенном обучении;
- журнал прохождения с датами, оценками и актуальной выгрузкой Excel;
- управленческий дашборд с ограничением данных областью ответственности;
- автоматический выход после пяти минут бездействия.

Система не содержит публичной регистрации, данных пациентов, почтовых уведомлений или встроенного видеохостинга.

## Технологии

- Python 3.12+
- Django 5
- PostgreSQL в Docker или SQLite для локальной демонстрации
- Gunicorn и Caddy/Nginx для production
- openpyxl для Excel-отчётов

## Быстрый запуск через Docker

1. Скопируйте `.env.example` в `.env`.
2. Замените все демонстрационные секреты и пароли в `.env`.
3. Запустите приложение:

```bash
docker compose up --build
```

4. Откройте `http://localhost:8080`.

При первом старте контейнер применяет миграции и запускает команду демонстрационного наполнения. Демо-пароль берётся из `DEMO_PASSWORD`; реальные пароли нельзя хранить в репозитории.

## Локальный запуск без Docker

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` установите `USE_SQLITE=1`, задайте уникальный `DJANGO_SECRET_KEY` и локальный `DEMO_PASSWORD`, затем выполните:

```powershell
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py seed_demo
.venv\Scripts\python manage.py runserver
```

Приложение будет доступно по адресу `http://127.0.0.1:8000/`.

## Проверка

```powershell
.venv\Scripts\python manage.py check
.venv\Scripts\python manage.py test
```

Тесты проверяют доступ по ролям, вход и идентификацию пользователя, назначение обучения, ограничения тестирования, уведомления и время жизни сессии.

## Конфигурация

Основные переменные окружения перечислены в `.env.example`:

- `DJANGO_SECRET_KEY` — уникальный секрет Django;
- `DJANGO_DEBUG` — `0` в production;
- `DJANGO_ALLOWED_HOSTS` — разрешённые домены;
- `POSTGRES_*` — подключение к PostgreSQL;
- `DEMO_PASSWORD` — временный пароль только для демонстрационных записей;
- `USE_SQLITE` — `1` для локального SQLite, `0` для PostgreSQL.

Файлы `.env`, базы данных, загруженные документы, логи, архивы развёртывания и локальные SSH-данные исключены из Git.

## Production

Для production используйте отдельный `.env`, HTTPS, `DJANGO_DEBUG=0`, уникальные пароли и регулярные резервные копии базы и каталога `media`. Перед обновлением необходимо создать резервную копию, применить миграции и выполнить smoke-тест основных маршрутов.

Текущее развёртывание: `https://oncomap-abai.kz/quality/`. Портал обучения
работает с PostgreSQL 16; конфигурация для общей VPS находится в
`docker-compose.quality.yml`. Ежедневный `pg_dump` и зашифрованная копия
описаны в [инструкции по эксплуатации](docs/OPERATIONS.md). SQLite оставлен
только для локального запуска и как сохранённый снимок до миграции.
