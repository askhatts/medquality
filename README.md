# MedQuality

Закрытый портал непрерывного повышения качества медицинских услуг. Проект объединяет обучение сотрудников, итоговое тестирование, внутренние документы и актуальную отчётность в одном интерфейсе.

## Возможности

- четыре роли: системный администратор, методист, руководитель подразделения и сотрудник;
- сотрудники, должности, типы сотрудников, отделы и отделения;
- административный справочник подразделений: создание, переименование и безопасное объединение с переносом сотрудников;
- каталог курсов с категориями;
- материалы курса: учебные документы, YouTube-видео, НПА РК и документы из внутреннего банка;
- банк внутренних документов с версиями, статусами, сроками пересмотра, тегами и повторным подключением к разным курсам;
- конструктор итогового теста с вопросами одного или нескольких правильных ответов и форматом «верно/неверно»;
- публикация и версионирование тестов с неизменяемой историей попыток;
- назначение курса отделам, отделениям или отдельным сотрудникам;
- массовое продление и отмена по нескольким курсам, категориям и подразделениям, включая отдельный режим для не прошедших обучение;
- добавление дополнительных попыток без изменения прежних оценок и завершённых циклов обучения;
- индивидуальные срок, проходной балл и допустимое количество попыток;
- внутренние уведомления о назначенном обучении;
- журнал прохождения с датами, оценками и актуальной выгрузкой Excel;
- управленческий дашборд с ограничением данных областью ответственности;
- автоматический выход после 30 минут бездействия;
- добровольный анонимный опрос профессионального благополучия: вход без логина, аналитика только для сисадмина, PDF с графиками.

Система не содержит публичной регистрации, данных пациентов, почтовых уведомлений или встроенного видеохостинга.

## Технологии

- Python 3.12+
- Django 5
- PostgreSQL в Docker или SQLite для локальной демонстрации
- Gunicorn и Caddy/Nginx для production
- openpyxl для Excel-отчётов
- ReportLab и DejaVu Sans для PDF с кириллицей и векторными графиками

## Опрос профессионального благополучия

После миграций выполните `python manage.py prepare_ethics_and_survey`. Команда идемпотентно добавляет материалы курса этики из Google Drive, тест из 10 вопросов и опрос. История назначений сохраняется; команда не создаёт результаты или анкеты.

Кнопка «Вход без логина» на экране входа ведёт на `/quality/guest/` — открытые разделы портала. Внутри доступен раздел профессионального благополучия и выгорания с анкетой `/quality/survey/`; в дальнейшем здесь можно разместить открытые материалы. Раздел `/quality/surveys/analytics/` и PDF доступны только роли ADMIN. По умолчанию текущие год и полугодие выбираются автоматически (`?year=auto&half=auto`), прошлые годы доступны в архиве. Заголовки — «1 полугодие» и «2 полугодие»; отчёт содержит фактические даты периода. Аналитика обновляется каждые 30 секунд и при возвращении к вкладке, не сбрасывая форму настроек. Отдельно показаны общее число анкет и количество за выбранное полугодие; новый ответ учитывается по дате отправки. PDF всегда формируется заново по выбранному периоду. В настройках можно закрыть приём, изменить даты и задать численность аудитории для расчёта отношения количества анкет к численности. Это отношение не подтверждает число уникальных сотрудников: без идентификации это невозможно проверить.

Ответы не связаны с пользователем, IP, сессией или точным временем. Случайный подписанный cookie предотвращает случайные дубли из одного браузера в текущем полугодии; в новом полугодии выдаётся новый случайный идентификатор, не связывающий ответы разных периодов. Это не гарантирует защиту от повторного заполнения после очистки cookie либо с другого устройства. Персональные данные нельзя включать в свободный комментарий. Исходные комментарии и индивидуальные анкеты не публикуются в админке и PDF; темы предложений группируются по ключевым словам.

После отправки сам ответивший видит общий балл /50, подшкалы поддержки и нагрузки /25 и пояснения по порогам 40/20/20. Расчёт общий для личной карточки и сводных отчётов: вопросы 1–10, 1–5 и 6–10 соответственно; дополнительные вопросы не учитываются ([Mini-Z 2.0 для индивидуального подсчёта](https://www.ssmhealth.com/getmedia/2fd26020-d205-45fb-b34c-5179568bcd19/minizburnoutassessment2.pdf)). Отдельно показано описание ответа на вопрос № 2 о выгорании. Это самооценка, не диагноз и не классификация выгорания по общему баллу ([описание инструмента NAM](https://nam.edu/product/valid-and-reliable-survey-instruments-to-measure-burnout-well-being-and-other-work-related-dimensions/), [пояснение ВОЗ](https://www.who.int/standards/classifications/frequently-asked-questions/burn-out-an-occupational-phenomenon)). Доступ — только по подписанному cookie браузера, без ID ответа в URL; вход с тем же логином в другом браузере не открывает результат. На общем устройстве результат может быть виден следующему посетителю этого браузера: кнопка «Скрыть личный результат» скрывает все личные баллы и самооценку, не удаляя ответ и не разрешая повторную отправку. В новом полугодии доступен результат новой анкеты. В админских отчётах личных карточек нет.

Расчёт соответствует предоставленной рабочей адаптации Mini-Z ЦЯМиО (2026): сумма 1–10 — 10–50, подшкалы 1–5 и 6–10 — по 5–25, без дополнительного обратного кодирования. Порог благоприятной оценки — 40/20/20. Признаки выгорания — ответы 1–3 на вопрос 2; напряжение из-за МИС — ответы 1–2 на вопрос 9. Дополнительные вопросы в балл не входят. Показатели публикуются от пяти анкет за выбранное полугодие только в целом, без разбивки по категориям сотрудников и подразделениям. Анкета не является диагностическим инструментом.

Для PDF локально на Windows используется Arial; на Linux установите `fonts-dejavu-core` (в Docker устанавливается автоматически).

### Замена истории в тестовой установке

Команда `python manage.py replace_test_history` выводит план полного обновления назначений, попыток и анкет. Она предназначена только для установки, история которой объявлена тестовой. После резервного копирования `--apply --replace-history` заменяет прежние записи: каждый активный сотрудник (кроме административных и технических записей) получает два назначения на каждый активный курс — в марте и сентябре выбранного года, только в будни. Охват составляет 90–100%, оценка — 80/90/100 за одну попытку, число анкет — 90–150. У всех курсов должен быть опубликованный тест из десяти равнозначных вопросов. Учётные записи, материалы и версии тестов сохраняются. Изменения выполняются одной транзакцией; повтор идентичного набора не создаёт дубликаты. В пользовательских таблицах используются обычные поля без дополнительных обозначений. Данные формируются программно и не подтверждают фактическое прохождение сотрудниками или результаты кадрового опроса.

## Быстрый запуск через Docker

1. Скопируйте `.env.example` в `.env`.
2. Замените все демонстрационные секреты и пароли в `.env`.
3. Запустите приложение:

```bash
docker compose up --build
```

4. Откройте `http://localhost:8080`.

При первом старте контейнер применяет миграции и запускает команду демонстрационного наполнения. Демо-пароль берётся из `DEMO_PASSWORD`; реальные пароли нельзя хранить в репозитории.

## Локальный запуск без Docker

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` установите `USE_SQLITE=1`, задайте уникальный `DJANGO_SECRET_KEY` и локальный `DEMO_PASSWORD`, затем выполните:

```powershell
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py seed_demo
.venv\Scripts\python manage.py runserver
```

Приложение будет доступно по адресу `http://127.0.0.1:8000/`.

## Аналитика и наполнение

### Выгрузка текстовых предложений опроса

В «Опрос персонала» за выбранное полугодие доступны «PDF с графиками и текстовыми
ответами» и «Текстовые ответы Excel». Обычный PDF остаётся только сводным.
Подборка доступна исключительно сисадмину и только от пяти анкет за период.
Одинаковые обезличенные тексты объединяются с количеством повторений; порядок
алфавитный. Тексты не связываются с оценками, демографией, датами отправки, ID
анкет или cookie. Сохранённые ответы не изменяются.

Автоматически скрываются контакты, ссылки, длинные номера и типовые форматы ФИО;
это не гарантирует отсутствия косвенных идентификаторов. Перед дальнейшим
распространением отчёта администратор должен проверить свободный текст.
Excel экранирует строки, похожие на формулы, PDF — разметку. Выгрузки формируются
из текущей базы без кэширования. В форме опроса явно указано использование
обезличенных предложений в закрытом отчёте.

### Личный список назначений

Вкладка «К прохождению» и колокольчик учитывают один и тот же набор: последнее
назначение курса с опубликованным тестом, ещё открытым сроком и доступными попытками.
Срок учитывается с точностью до времени, в часовом поясе портала. Просроченные,
исчерпавшие попытки и временно недоступные тесты остаются на вкладке «Не завершены»,
а успешные результаты — в «Пройденных». Отменённое или завершённое новое назначение
не открывает более старую активную запись. Ссылки из истории передают номер
конкретного назначения, доступного только его владельцу; просмотр истории не
разрешает повторно сдавать старый тест. Результаты и сроки этим разделением не меняются.

### Результаты отдельных назначений

В «Отчёты → Аналитика назначений» выберите курс и конкретное назначение.
Повторные назначения одного курса не смешиваются: новые массовые назначения
сохраняют общий идентификатор группы. Для старых записей без такого идентификатора
доступен архив по дню назначения с последней записью каждого сотрудника за день;
это ограничение явно показано на экране. Миграция `0020` не переписывает историю.

По отделениям рассчитываются количество назначенных сотрудников, ожидающие,
начавшие, успешно завершившие, не прошедшие, просроченные и переназначенные,
средняя последняя оценка и доля успешных завершений. Среднее учитывает только
сотрудников с завершённой попыткой, не заменяя отсутствие оценки нулём.
Подробности по вопросам берутся из снимка последней попытки выбранного назначения.
Для старых итоговых оценок без снимков детализация по вопросам недоступна.
Excel содержит отдельные листы параметров, отделений, сотрудников и вопросов;
каждая выгрузка строится заново, даты и оценки сохраняются как типизированные поля.

Отменённые назначения и неактивные сотрудники исключены. Используется текущее
отделение из профиля. Администратор и методист видят организацию, руководитель —
только своё отделение; сотрудникам аналитика недоступна. Анонимная анкета выгорания
не связывается с учебными результатами и не разбивается по подразделениям.

### Курс по обращению с медицинскими отходами

Команда `python manage.py load_medical_waste` показывает предварительный план.
Для добавления курса и назначения всем активным сотрудникам, кроме технического
администратора и суперпользователей:

```bash
python manage.py load_medical_waste --apply --assign --due-date 2026-11-24 --due-time 23:59 --actor sysadmin
```

Материал остаётся ссылкой Google Drive: PDF не копируется в хранилище портала.
Десять вопросов и ключ перенесены из предоставленного документа; ссылка на ключ
не показывается слушателям. Это проверка знаний по учебному материалу, не отдельная
юридическая экспертиза его санитарных норм. Порог — 80%, две попытки, десять минут;
порядок вариантов перемешивает обычный механизм тестирования. Повтор команды
для того же срока не создаёт дубликаты и не сбрасывает результаты. При изменении
содержимого создаётся новая версия теста, старые назначения сохраняют свою версию.

## Проверка

### Восстановление утраченного результата

Если администратор подтверждает прохождение и оценку после сбоя связи,
`recover_training_results` регистрирует отдельное восстановление с основанием,
администратором, временем внесения и прежним состоянием назначения. Исходные
попытки не изменяются, ответы и неизвестное время сдачи не создаются.
В карточках и Excel источник такой оценки указан явно.

```bash
python manage.py recover_training_results --courses COURSE_ID --month YYYY-MM --score SCORE --actor ADMIN_LOGIN --reason "Подтверждённое основание восстановления"
# После проверки предварительного просмотра добавить --confirm-outage --apply.
```

Обрабатываются только последние действующие назначения указанного месяца
активным сотрудникам; отменённые и переназначенные исключены. Повтор той же
команды не создаёт дубликаты. Иные оценки/основания существующего восстановления
не перезаписываются. Необходима резервная копия перед применением.

```powershell
.venv\Scripts\python manage.py check
.venv\Scripts\python manage.py test
```

Тесты проверяют доступ по ролям, вход и идентификацию пользователя, назначение обучения, ограничения тестирования, уведомления и время жизни сессии.

## Конфигурация

Основные переменные окружения перечислены в `.env.example`:

- `DJANGO_SECRET_KEY` — уникальный секрет Django;
- `DJANGO_DEBUG` — `0` в production;
- `DJANGO_ALLOWED_HOSTS` — разрешённые домены;
- `POSTGRES_*` — подключение к PostgreSQL;
- `DEMO_PASSWORD` — временный пароль только для демонстрационных записей;
- `USE_SQLITE` — `1` для локального SQLite, `0` для PostgreSQL.

Файлы `.env`, базы данных, загруженные документы, логи, архивы развёртывания и локальные SSH-данные исключены из Git.

## Production

Для production используйте отдельный `.env`, HTTPS, `DJANGO_DEBUG=0`, уникальные пароли и регулярные резервные копии базы и каталога `media`. Перед обновлением необходимо создать резервную копию, применить миграции и выполнить smoke-тест основных маршрутов.

Текущее развёртывание: `https://oncomap-abai.kz/quality/`. Портал обучения
работает с PostgreSQL 16; конфигурация для общей VPS находится в
`docker-compose.quality.yml`. Ежедневный `pg_dump` и зашифрованная копия
описаны в [инструкции по эксплуатации](docs/OPERATIONS.md). SQLite оставлен
только для локального запуска и как сохранённый снимок до миграции.
